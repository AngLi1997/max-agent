# 后台工作台 UI 优化与权限菜单排查设计文档

日期：2026-04-30

## 概述

本次目标是将当前后台管理界面调整为更紧凑的工作台式布局，优先把可视空间让给表格内容，同时将“模型管理、Skills 管理、工具管理等页面未显示入口”的问题按权限配置链路排查，而不是直接以前端展示缺陷处理。

本次范围覆盖：
- 顶部 Tabs 与内容区的层级调整
- 页面标题区收紧与视觉减重
- 动态表格高度实现重做
- Tag 统一改为蓝系主题风格
- 模型管理、Skills 管理、工具管理等后台列表页统一骨架
- 菜单缺失问题的权限配置排查链路与验证方式

本次不覆盖：
- 新增业务页面
- 重写整套路由系统
- 为管理员增加前端无条件展示全部菜单的特判
- 将模型管理、Skills 管理、工具管理改造成真实后端接口

## 当前状态

### 1. 布局现状

当前 `TabBar` 位于内容工作区内部，定义在 `frontend/src/layouts/BasicLayout.vue:139-155`，导致 Tabs 占用了页面卡片内部的垂直空间。页面标题区也位于同一壳层内，形成了“Tabs + 重标题 + 内容区”的叠加结构，对列表页而言视觉重量偏大。

当前标题左侧装饰条定义在 `frontend/src/layouts/BasicLayout.vue:197-203`，宽度为 `8px`，在新的紧凑工作台布局里显得过重。

### 2. 动态表格高度现状

当前动态表格高度逻辑位于 `frontend/src/composables/useTableScrollY.ts:7-16`，通过 `window.innerHeight - rect.top - reservedBottomSpace` 计算滚动高度，并依赖固定的 `reservedBottomSpace = 88`。这种方式对壳层高度变化较敏感，在 Tabs、标题区、工具栏层级调整后容易出现两类问题：
- 表格没有撑满剩余高度
- 页面总高度超出视口

### 3. 列表页骨架现状

模型管理、Skills 管理、工具管理以及系统设置下多个列表页都采用近似的“查询区 + 表格区 + 抽屉表单”结构，例如：
- `frontend/src/views/model/index.vue`
- `frontend/src/views/skill/index.vue`
- `frontend/src/views/tool/index.vue`

这些页面已经具备统一骨架的基础，但仍依赖当前页面壳层结构，因此当壳层层级和高度策略不合理时，会同时受到影响。

### 4. 菜单显示现状

模型管理、Skills 管理、工具管理路由已经定义在 `frontend/src/router/index.ts:19-21`，说明页面组件本身并不存在“未注册路由”的问题。

左侧菜单的实际显示来源于登录态中的 `userStore.menus`，见 `frontend/src/stores/user.ts:10` 与 `frontend/src/stores/user.ts:18-23`。这意味着“管理员看不到入口”首先应被视为权限配置、菜单配置或登录返回数据的问题，而不是前端页面组件缺失问题。

## 目标与约束

### 目标

1. 将后台列表页调整为紧凑工作台式布局。
2. 将 Tabs 移出内容卡片内部，减少内容区垂直浪费。
3. 弱化页面标题区，仅保留轻量页面标识。
4. 让表格区域准确撑满剩余高度，不再超出视口。
5. 将常规状态类 Tag 统一到蓝系主题。
6. 将模型管理、Skills 管理、工具管理等列表页统一到同一套页面骨架。
7. 将菜单缺失问题优先按“权限配置 -> 登录返回 -> 前端渲染”链路排查。

### 约束

- 菜单问题优先检查权限配置，不先写管理员前端特判。
- 列表页布局方向采用“顶部 Tabs + 轻页面标识 + 查询区/操作区 + 表格”的工作台结构。
- 列表页不再保留当前较重的独立标题区。
- 状态标签尽量避免绿色和红色，统一使用蓝系深浅层次表达状态差异。

## 设计方案

### 1. 页面整体骨架

后台主内容区调整为三层结构：
1. 顶部全局 Header
2. Header 下方的 Tabs 工作台层
3. 页面内容工作区

其中 Tabs 不再位于页面卡片内部，而是提升为内容区外层的一条独立工作台带。这样列表页进入后，页面纵向结构变为：
- Tabs
- 轻页面标识
- 查询区 / 操作区
- 表格区

该设计直接解决当前 Tabs 挤占内容区高度的问题，并让所有列表页共享同一套可预测的空间分配规则。

### 2. 轻页面标识

列表页不再使用当前较重的标题壳层，而改为一条更轻、更薄的页面标识行，仅用于提示当前所在页面，不再承担明显的分区视觉。

具体规则：
- 保留左侧主题色装饰条
- 装饰条宽度从 `8px` 缩减到 `4px`
- 标识行整体高度、上下内边距和字体重量同步减轻
- 标识行不再表现为独立的大型卡片头部

该策略满足“弱化标题区、把主要可视面积让给表格”的目标，同时保留必要的页面定位能力。

### 3. Tabs 外提与样式角色调整

`frontend/src/components/TabBar.vue` 从当前页面壳层内部移到更外层后，其视觉角色从“内容卡片的一部分”转为“工作台导航带”。因此样式需要同步调整：
- 维持横向滚动能力和右键菜单能力
- 保留活动标签与普通标签的区分
- 减少 Tabs 自身对内容卡片边框的依赖
- 让 Tabs 与页面内容区之间形成清晰但轻量的层级关系

Tabs 仍然保留多标签切换、关闭、关闭左右、关闭其他、关闭全部和 `keep-alive` 缓存机制，不改变其交互职责。

### 4. 动态表格高度策略

动态表格高度不再以固定预留值为主，而改成“壳层 flex 严格撑满 + 表格容器按实际剩余空间计算”的策略。

具体设计：
- 自顶向下梳理 `a-layout`、`layout-content-shell`、`workspace-shell`、页面容器、表格区的 `height` / `flex` / `min-height: 0` 链路
- 保证每一级容器都允许子级在剩余空间内收缩和扩展
- 将表格滚动区高度计算基于表格容器的实际可用高度，而不是固定减去某个经验值
- 保证工具栏高度变化、Tabs 位置变化、标题区压缩后，表格仍能自动适配

目标结果：
- 表格刚好填满剩余空间
- 页面整体不出现明显超高
- 不因为壳层高度变化而需要频繁修改固定预留值

### 5. Tag 主题化策略

常规状态类 Tag 改为统一蓝系主题，而不是使用绿色/红色作为默认成功/失败或进入/退出状态表达。

具体规则：
- 同一类后台状态统一使用蓝系主色、浅底、细边框的组合
- 通过明度、透明度、描边和文字深浅区分不同状态
- 登录日志中的“成功”“退出”等常规标签也纳入同一主题体系
- 避免出现视觉上强烈割裂的红绿对抗配色

该策略的核心不是消除状态差异，而是将差异收敛到同一主题色系中，保持后台整体一致性。

### 6. 列表页统一工作台骨架

模型管理、Skills 管理、工具管理，以及系统设置下的典型列表页统一采用以下骨架：
- 顶部 Tabs
- 轻页面标识
- 查询/筛选工具栏
- 表格主体区
- 抽屉表单

统一规则：
- 不允许部分页面保留重标题、部分页面改为轻标题
- 不允许不同列表页各自定义完全不同的高度计算方式
- 公共壳层负责布局和空间分配，页面组件只关注各自的筛选项、列定义和表单内容

该设计可以减少未来继续新增后台页面时的样式分裂风险。

## 菜单缺失问题的处理策略

### 1. 问题定义

“模型管理、Skills 管理、工具管理等页面没有正常显示”的首要解释不是页面未实现，而是管理员登录后未获得对应菜单可见性结果。

因为：
- 路由已经存在于 `frontend/src/router/index.ts:19-21`
- 左侧菜单实际来源于 `userStore.menus`
- 菜单显示是否正确首先取决于后端返回的菜单树与权限聚合结果

### 2. 排查顺序

菜单缺失问题按以下顺序排查：
1. 后端菜单配置中是否存在模型管理、Skills 管理、工具管理对应菜单
2. 管理员角色是否绑定了这些菜单关联的权限或菜单可见性规则
3. 登录接口或 `auth/me` 返回的 `menus` 是否真实包含这些 path
4. 前端菜单树渲染是否因父子层级、path、icon 或结构异常导致未显示

该顺序确保优先修正权限配置问题，而不是在前端做掩盖性修复。

### 3. 前端策略

本次前端不直接增加“管理员无条件显示全部菜单”的兜底逻辑。

原因：
- 这会掩盖权限配置错误
- 会让菜单配置问题难以通过真实登录态复现和验证
- 与当前“菜单由后端返回并驱动前端显示”的架构方向不一致

只有在权限配置链路被明确判定不满足项目要求时，才考虑引入新的展示策略。

## 实施边界

### 本次应修改的层面

- `frontend/src/layouts/BasicLayout.vue`：调整 Tabs、轻页面标识和工作区层级
- `frontend/src/components/TabBar.vue`：适配外提后的工作台导航样式
- `frontend/src/composables/useTableScrollY.ts`：重做动态高度策略
- `frontend/src/style.css`：补齐公共布局与列表页工作台样式
- 各列表页视图：对齐统一骨架并接入蓝系 Tag 表达

### 本次不直接改动的结论性逻辑

- 不直接给管理员前端菜单特判
- 不重写为完全动态路由
- 不修改模型管理、Skills 管理、工具管理的业务接口形态

## 验证方案

### 1. 布局验证

- Tabs 位于内容区外层顶部，不再占用页面卡片内部空间
- 列表页标题明显变轻，不再出现厚重标题头
- 标题装饰条宽度缩减后仍能清晰表达页面定位
- 页面整体高度不超出视口
- 表格区域可以稳定填满剩余空间

### 2. 交互验证

- 模型管理、Skills 管理、工具管理页面进入后正常加入 Tabs
- Tabs 的切换、关闭、右键菜单、缓存能力保持可用
- 抽屉表单打开后不破坏页面整体高度关系

### 3. 权限与菜单验证

- 管理员登录后，检查返回的 `menus` 是否包含模型管理、Skills 管理、工具管理入口
- 若返回包含这些 path，则左侧菜单应正常显示对应入口
- 若返回不包含这些 path，优先回查权限与菜单配置，而不是直接修改前端菜单逻辑
- 非管理员角色的菜单可见性不被错误放大

### 4. 视觉验证

- 登录日志等页面中的常规状态 Tag 统一呈现为蓝系主题
- 不再出现绿色/红色作为默认成功/退出状态色
- 各列表页在视觉密度、层级和间距上保持一致

## 结论

本设计将后台管理界面收敛为统一的工作台式列表页结构：顶部 Tabs、轻页面标识、查询工具栏和可自适应高度的表格主体区。同时，对于模型管理、Skills 管理、工具管理入口缺失的问题，优先按权限配置链路排查，而不是先通过前端特判掩盖配置错误。这样既能解决当前布局空间浪费与高度失准问题，也能保证后台菜单显示逻辑继续以真实权限结果为准。
